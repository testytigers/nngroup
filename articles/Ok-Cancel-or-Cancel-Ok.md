<div class="article-summary article-heading-small-light">

<span class="article-summary-label">

Summary:&nbsp;

</span>Should the OK button come before or after the Cancel button? Following platform conventions is more important than optimizing an individual dialog box.

</div>

<div class="article-body">

<p>We get countless questions about small details in UI design that <em> don't matter much </em> to the overall user experience. One classic is the <strong> order of buttons </strong> in dialog boxes:</p>

<ul>

<li><em>OK / Cancel </em></li>

<li><em>Cancel / OK</em></li>

</ul>

<p>Both are reasonable choices, and people can argue for hours about their preferences:</p>

<ul>

<li>Listing <em> OK </em> <strong> first </strong> supports the <strong> natural reading order </strong> in English and other languages that read left-to-right. Many other button sets have a natural progression (say, <em> Yes / No </em> or <em> Previous / Next)</em>. You should always list these so that the reading order matches the logical order — in this case, <em> OK / Cancel</em>. Further, assuming users need <em> OK </em> much more frequently than <em> Cancel</em>, it's better to place this option first so that keyboard-driven users who tab to the buttons can get to their preferred choice with one less keystroke.</li>

<li>Listing <em> OK </em> <strong> last </strong> improves the flow, because the dialog box <strong> "ends" with its conclusion</strong>. Also, as with <em> Previous/Next</em>, you could argue that <em> OK </em> is the choice that moves the user forward, whereas <em> Cancel </em> moves the user back. Thus, <em> OK </em> should be in the same location as <em> Next</em>: on the right.</li>

</ul>

<p>In cases like this, it often <strong> doesn't matter </strong> what you do. Either choice has good arguments in its favor, and no choice is likely to cause usability catastrophes. It might save some users 0.1 seconds if you pick the "right" choice for certain circumstances, but it's simply not worth it to conduct sufficiently elaborate research to find out what that choice is. Better to spend your usability resources on those things that can <a class="old" href="/articles/usability-roi-declining-but-still-strong/" title="Alertbox: Usability ROI Declining, But Still Strong"> change your key performance indicators by 83%</a> or more. (Critical application design issues are covered further in the full-day <a href="https://www.nngroup.com/courses/application-ux/">course on Application Design</a>.)</p>

<p>So, to make this specific choice — as well as many other small choices in application design — it's best to follow the <strong> platform GUI standard</strong>. Applying consistent design that follows user expectations saves people much more time (and many more mistakes) than doing something that might be a tiny bit more optimal for your application but introduces an inconsistency.</p>

</div><h2 id="toc-inconsistency-costs-more-time-than-it-saves-1">Inconsistency Costs More Time than It Saves</h2>

<p><strong>Deviate from the standard, and you'll easily cost users several minutes </strong> — or possibly hours — as they overlook or misuse UI elements. The time people spend pondering inconsistencies typically sums to much more than the small savings you'll hypothetically derive from a specialized design.</p>

<p>Sadly, the <cite> Windows User Experience Guidelines </cite> differ from the <cite> Apple Human Interface Guidelines </cite> when it comes to the sequence of <em> OK / Cancel </em> buttons:</p>

<ul>

<li>Windows puts <em> OK </em> first</li>

<li>Apple puts <em> OK </em> last</li>

</ul>

<p>If you're designing a desktop application for one of these two personal computer platforms, your choice is easy: <strong> Do what the platform owner tells you to do</strong>.</p>

<h2 id="toc-dialog-buttons-for-web-based-apps-2">Dialog Buttons for Web-Based Apps</h2>

<p>If you're designing a <strong>web-based application</strong>, the decision is harder, but you should probably go with the <strong> platform preferred by most of your users</strong>. Your server logs will show you the percentage of Windows vs. MacOS users for your specific website or intranet. Of course, Windows generally has many more users, so if you can't be bothered to check the logs, then the guideline that will apply to most situations is:</p>

<ul>

<li><strong><em>OK </em> first, <em> Cancel </em> last</strong>, as in this screenshot from Office 2007:</li>

</ul>

<p style="text-align:center; margin-top:0ex"><img alt="Screenshot from Office 2007, showing buttons labeled 'Save' and 'Cancel'." height="51" loading="lazy" src="//media.nngroup.com/media/editor/alertbox/ok-cancel-buttons.gif" width="199"/></p>

<p>The screenshot illustrates two additional guidelines for dialog box buttons:</p>

<ul>

<li>It's often better to <strong>name a button to explain what it does </strong> than to use a generic label (like "OK"). An explicit label serves as just-in-time help, giving users more confidence in selecting the correct action.</li>

<li><strong>Make the most commonly selected button the <a class="old" href="/articles/the-power-of-defaults/" title="Alertbox: The Power of Defaults"> default</a> and highlight it</strong> (except if its action is particularly dangerous; in those cases, you want users to explicitly select the button rather than accidentally activating it by hitting <em>Enter</em>).</li>

</ul>
