<div class="article-summary article-heading-small-light">

<span class="article-summary-label">

Summary:&nbsp;

</span>It&#x27;s cheap but degrading to reuse content and design across diverging media forms like print vs. online or desktop vs. mobile. Superior UX requires tight platform integration.

</div>

<div class="article-body">

<p>When it comes to user experience strategy, there are two opposing schools:</p>

<ul>

<li><strong>Repurposing</strong>: make as few designs as possible — preferably only one — and reuse the same material across as many platforms as possible.</li>

<li><strong>Platform optimization</strong>: design different user interfaces for each main platform, integrating the user experience layers as tightly as possible.</li>

</ul>

<p>Repurposing has huge <strong> cost advantages</strong>. Most of the work must be done only once. But on most platforms, the outcome tends to be a <strong> substandard user experience</strong>. This is particularly true if the design was initially optimized for one platform and later ported onto other platforms with minimal changes.</p>

<p>Over the 17 years I've been writing the Alertbox column, the campaign against repurposing has been a key recurring theme. In the early years, the main problem was brochureware websites that tried to repurpose print design strategies:</p>

<ul>

<li>I analyzed the <a class="old" href="/articles/differences-between-print-design-and-web-design/" title="Alertbox: Differences Between Print Design and Web Design"> differences between print vs. web design</a> and the differences in <a class="old" href="/articles/writing-style-for-print-vs-web/" title="Alertbox: Writing Style for Print vs. Web"> writing for print vs. writing for the web</a>.</li>

<li>I also argued that the <a class="old" href="/articles/tv-meets-the-web/" title="Alertbox: TV Meets the Web "> online experience is different than television</a>, even though both media show glowing pictures on a monitor, because the different <a class="old" href="/articles/media-velocity-tv-vs-the-web/" title="Alertbox: Velocity of Media Consumption: TV vs. the Web"> speeds of media consumption</a> lead to different content preferences.</li>

<li>Finally, I pointed out that the interactive medium should aim to be "<a class="old" href="/articles/better-than-reality-a-fundamental-internet-principle/" title="Alertbox: Better Than Reality: A Fundamental Internet Principle">better than reality</a>" instead of mimicking old media forms.</li>

</ul>

</div><h2 id="toc-platform-optimized-user-experience-1">Platform-Optimized User Experience</h2>

<p><strong>Apple's </strong> history provides the most famous examples of tightly integrated design:</p>

<ul>

<li>The <strong> Macintosh </strong> required mouse-driven software and didn't even offer cursor keys for several years to prevent software vendors from simply porting their DOS products.</li>

<li>The <strong> iPod </strong> and <strong> iPhone </strong> integrated the physical device, the on-screen user interface, and an infrastructure for downloading music and apps (even though the <a class="old" href="/articles/disruptive-workflow-design/" title="Alertbox: Disruptive Workflow Design"> iTunes application is the poor stepsister</a> in this relationship and could stand some design love).</li>

</ul>

<p>In contrast, Microsoft <strong> Windows </strong> emphasized its broad ability to work across many different hardware systems with the addition of plug-and-play/pray devices to suit the user's taste. Thus, developers could never be sure which hardware and service support their applications would find on a Windows machine. <a class="out" href="http://blogs.msdn.com/b/b8/archive/2012/05/18/creating-the-windows-8-user-experience.aspx" title="Microsoft: A brief history of the Windows user interface"> Windows 1 was even designed</a> to primarily be used without a mouse. The resulting total user experience was substantially less integrated than Macintosh.</p>

<p><strong>Windows CE </strong> was a particularly egregious example of the repurposing strategy: taking a design that worked fairly well on desktop computers and porting it to pocket-sized devices — where it worked miserably.</p>

<p>Over the past decade, Microsoft has fought to overcome its legacy of confused user experience, and its current products are considerably improved. On the other hand, <strong> Windows 8 </strong> might be overly optimized for touchscreen use and risks working poorly on mainstream desktop computers. The idea of repurposing a single design across platforms may have been taken too far once again.</p>

<p>After the <strong> iPhone </strong> shipped, many other telecoms vendors launched competing products that mimicked the touchscreen hardware but offered poorly integrated software that was ported from systems optimized for other platforms.</p>

<p>The following video comes from a round of our <a class="old" href="/articles/mobile-web-2009-desktop-web-1998/" title="Alertbox: Mobile Web 2009 = Desktop Web 1998"> mobile user testing in early 2009</a>, which included some of these iPhone semi-clones. Here, the poor user is simply trying to use a <a class="old" href="/articles/store-finders-and-locators/" title="Alertbox: Store Finders and Locators"> store locator</a> to find the nearest department store:</p>

<figure>

<video controls="" src="https://media.nngroup.com/media/editor/2018/02/19/touchscreen-dropdown-difficulties.mp4" width="100%">Your browser does not support the video tag.</video>

<figcaption><em>User attempting to use a store locator on an early iPhone competitor with a horrible user interface. (Note: video has no soundtrack; in most browsers, hover over the video to display the controls if they're not already visible.)</em></figcaption>

</figure>

<p>(To protect our test participant's privacy and to keep this a family-oriented website, I have erased the soundtrack, but rest assured that the user pronounced negative comments on this UI.)</p>

<p>Clearly, it was not enough to simply offer a big touchscreen on the phone. The software user interface should have been optimized for this platform's characteristics as well.</p>

<h2 id="toc-costbenefit-analysis-2">Cost–Benefit Analysis</h2>

<p>The <strong> benefits of platform-optimized user interfaces </strong> are clear:</p>

<ol>

<li>Usability is increased.</li>

<li>Users are more likely to accomplish their goals.</li>

<li>Conversion rates increase.</li>

<li>You make more money.</li>

</ol>

<p>But, of course, optimization is more costly than repurposing. So, the real question is whether this <strong> cost is bigger or smaller </strong> than the additional money you make from increased usability.</p>

<p>(When I talk about "making money," from a website, I'm not limiting the case to <a class="new" href="http://www.nngroup.com/reports/ecommerce-user-experience/" title="Nielsen Norman Group report: 874 Design Guidelines for E-commerce Sites"> e-commerce sites</a>. The <a class="old" href="/articles/usability-roi-declining-but-still-strong/" title="Alertbox: Usability Return-On-Investment (ROI) Declining, But Still Strong"> ROI case</a> works just as well for <a class="old" href="/articles/b2b-usability/" title="Alertbox: Business-to-Business Usability"> B2B sites</a> — measured in new leads, for example — as well as for <a class="old" href="/articles/non-profit-websites-donations/" title="Alertbox: Non-Profit Organization Websites: Increasing Donations and Volunteering"> non-profit sites collecting donations</a> and <a class="old" href="/articles/government-non-profits-usability-roi/" title="Alertbox: Do Government Agencies and Non-Profits Get ROI From Usability?"> government sites fulfilling their mission</a> at a lower cost.)</p>

<p>In many cases, the cost–benefit analysis favors a unified design. For example, when designing a desktop website, there's no reason to create different versions for PC vs. Mac users because the two platforms are so similar these days. Similarly, you can use responsive design or related techniques to have a single site serve users with 19-inch monitors and users with 24-inch monitors, even though the former will see less info above the fold.</p>

<p>The benefit of separately optimized designs in such cases is simply too small to warrant multiple desktop designs; the same is true for iPhone vs. Android in the mobile realm. (Though you should make a few tweaks for things like native icons, as emphasized in our <a class="new" href="http://www.nngroup.com/courses/vis-mob-1/" title="Nielsen Norman Group training tutorial"> Visual Design for Mobile Devices</a> course.)</p>

<p>For tablets, consider iPad vs. Kindle Fire: our user research shows that the 7-inch screen on <a class="old" href="/articles/kindle-fire-usability-findings/" title="Alertbox: Kindle Fire Usability Findings"> Kindle Fire has sufficiently different usability requirements</a> and that there would be some benefits to designing a separate site for it (and probably for other mid-sized tablets as well, even though we didn't test them). On the other hand, our studies also found that sites optimized for popular mobile phones work reasonably well when stretched across Kindle Fire's screen. For most companies, the <a href="http://www.nngroup.com/articles/conversion-rates/" title="Conversion Rates: Definition, article">conversion rate</a> difference between serving the regular mobile site and creating a Fire-optimized site would be fairly small.</p>

<p>Is the small extra gain from designing and maintaining a separate user interface for Kindle Fire worth the extra cost? Amazon.com certainly thinks so, but they expect to sell a boatload to their semi-captive audience. For the vast majority of companies, however, this cost–benefit analysis would end in a different conclusion: repurpose the mobile site.</p>

<p>Another case where most companies decide against separate user interfaces is for <strong> users with disabilities</strong>. To support blind users perfectly requires a design that's optimized for linear presentation in an auditory medium. <a class="old" href="/articles/accessibility-is-not-enough/" title="Alertbox: Accessibility Is Not Enough"> Accessibility is insufficient</a> to create great usability from simply reading aloud a design that's optimized for 2D presentation in a visual medium.</p>

<p>In practice, there are so few blind users that it doesn't pay off to create a better design just for them. Giving perfect service to all disabled users would require an even wider set of distinct user interfaces, each optimized for a broad variety of disabilities. The cost is mind-boggling and the profits would be fairly small, because each class of disability contains a fairly small number of users. The common strategy of making the regular website accessible does penalize disabled users and makes them less productive and successful than non-disabled users. Although I don't like the accessibility strategy, I do recognize it as the only cost-effective solution, so I reluctantly recommend it.</p>

<p>Returning to the issue of <strong> repurposing print content </strong> for online use, most legacy newspapers and magazines have chosen to stick with this strategy. As a result, they've been less successful on the Internet than sites that create content using the <a class="new" href="/articles/how-users-read-on-the-web/" title="Articles about online content usability"> guidelines for writing for the Web</a>. Sites like CNN.com, Drudge Report, Huffington Post, and Craigslist are vastly more successful than newspaper sites, despite being not nearly as good or thorough in traditional terms.</p>

<p>Should newspapers discard their print content and create online content from scratch? There's no doubt that doing so would improve their websites. But the cost–benefit analysis would be negative because it's almost free to repurpose the existing articles, whereas the cost of running a second newsroom is substantial.</p>

<p>For another example, consider <strong> 3-D movies</strong>: the best have different cinematography than would be used for an equivalent 2-D movie. In 3-D, the camera should linger longer on establishing shots to give the audience time to look around the environment. (Something people empirically want to do in good 3-D movies.) At the other extreme, simply repurposing existing footage by making it pseudo-3D is almost always a recipe for failure.</p>

<h2 id="toc-responsive-design-sufficient-for-high-mobile-usability-3">Responsive Design: Sufficient for High Mobile Usability?</h2>

<p>When considering <a class="old" href="/articles/mobile-site-vs-full-site/" title="Alertbox: Mobile Site vs. Full Site"> mobile phones vs. desktop computers</a>, the platform differences are great enough that the benefits of creating two separate designs are substantial. Furthermore, both platforms have many wealthy users, so the profits from maximizing conversion rates can be considerable.</p>

<p>Still, the question remains <strong> whether the cost–benefit analysis truly supports two sites</strong>, or whether it would be more profitable to stick with a single site.</p>

<p>First, you must consider your organization's size and how much business you conduct with mobile and desktop users. Some companies are so small that a higher conversion rate wouldn't translate into enough money to pay for two designs. Others might provide services that are targeted solely to mobile or desktop users and thus wouldn't suffer much from a lower conversion rate among the few users on the opposite platform.</p>

<p>Even if your organization is big enough to profit from separate mobile and desktop designs, some people commenting on my "<a class="old" href="/articles/mobile-site-vs-full-site/" title="Alertbox: Mobile Site vs. Full Site">Mobile Site vs. Full Site</a>" column claimed that the cost was too high and thus recommended responsive design instead.</p>

<p>First of all, <strong> responsive design isn't free </strong> in terms of interaction design or in terms of coding and implementation. For some sites, it might be cheaper than other implementation strategies; if that's true for you, then do go that route.</p>

<p>But the most important point is that responsive design — if done correctly — does involve creating distinct user interfaces for each platform. After all, the entire idea is that the design adapts (or "responds") to the capabilities of the user's specific platform.</p>

<p>Most responsive design examples that I've seen are very primitive and don't go far enough to create the sufficiently distinct user interfaces that mobile vs. desktop use requires. It's <strong> not enough to simply modify the layout </strong> by moving stuff around on the screen and enlarging or diminishing particular design elements. This works only for adapting a desktop design to 19- vs. 24-inch monitors or for a mobile design for an iPhone vs. a Kindle Fire.</p>

<p>Mobile vs. desktop design <strong> differences go far beyond layout issues</strong>.</p>

<ul>

<li>Most important, the content should be different: <a class="old" href="/articles/condense-mobile-content/" title="Alertbox: Mobile Content: If in Doubt, Leave It Out"> shorter and simpler writing</a> is required for the smaller screen because the lack of context <a class="old" href="/articles/mobile-content-is-twice-as-difficult/" title="Alertbox: Mobile Content Is Twice as Difficult"> reduces text comprehension</a>.

<ul>

<li>Yes, people can read novels on a Kindle or other tablets, but that's mainly <a class="old" href="/articles/kindle-content-design/" title="Alertbox: Kindle Content Design"> useful for simple fiction with a linear plot</a> that's easy to follow. Reading business-oriented content or other non-fiction that requires higher levels of cognitive processing is more difficult on smaller screens.</li>

<li>In addition to text, other content formats should also be designed for the medium. For example, <strong> small images should be cropped and zoomed </strong> differently than large images to emphasize salient details. It's not enough to simply rescale a single image to fill the available space for a given screen size. (As an example, see <a class="old" href="/articles/iterative-design-mobile-screen/"> 4 design iterations of an image</a> representing a Korean pop group on a mobile screen.)</li>

</ul>

</li>

<li>The IA changes to <a class="old" href="/articles/defer-secondary-content-for-mobile/" title="Alertbox: Defer Secondary Content When Writing for Mobile Users"> defer secondary content to secondary pages</a> on mobile devices.</li>

<li>Interaction techniques change due to the <a class="old" href="/articles/mouse-vs-fingers-as-input-device/" title="Alertbox sidebar: Mouse vs. Fingers as Input Device"> differences between finger and mouse-driven</a> input.</li>

<li>The feature set is reduced in mobile to lower complexity and to fit on the smaller screen.</li>

</ul>

<p>With enough coding, all of these differences can be supported through responsive design. In fact, you could argue that a design isn't responsive enough if it doesn't accommodate all the salient platform differences. However, once you do account for all the differences, we're back to square one: two separate designs.</p>

<h2 id="toc-when-to-optimize-for-a-platform-4">When to Optimize for a Platform</h2>

<p><strong>Usability is about conversion rate </strong> maximization whereas <strong> design is about profit </strong> maximization. Therefore, prudent business decisions may sometimes generate a UI that's not all we'd like from a pure usability perspective.</p>

<p>It's <strong> okay to repurpose </strong> a single design for multiple platforms in two cases:</p>

<ul>

<li>When the platforms are <strong> very similar</strong>, so that small adaptations will suffice to make the same design work well in both places.</li>

<li>When you expect to get <strong> very little business </strong> value from a platform or you simply <strong> cannot afford </strong> to create a second design. As long as you realize that you're giving some customers a substandard user experience (and can live with the associated drop in conversion rates), this is a rational — if unpleasant — business decision.</li>

</ul>

<p>Conversely, you should create different designs <strong> optimized for each platform </strong> in these two cases:</p>

<ul>

<li>When the platforms are <strong> very different </strong> and require different interaction techniques, features, IA, and content, or dramatically different layouts that are too hard to achieve through responsive design.</li>

<li>When you expect to generate <strong> so much business </strong> from users on a certain platform that you want to drive conversion rates to their absolute max. Even when platforms are relatively similar, distinct user interfaces are a smart choice when the stakes are high.</li>

</ul>

<p>It defies all common sense to expect the same user interface to be optimal for 3.5-inch screens and <a class="old" href="/articles/computer-screens-getting-bigger/" title="Alertbox: Computer Screens Getting Bigger"> 30 inch screens</a>, with no modifications beyond moving a few things around. Diversity in our interactive platforms requires diverse interaction design.</p>
