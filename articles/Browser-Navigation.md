<div class="article-summary article-heading-small-light">

<span class="article-summary-label">

Summary:&nbsp;

</span>Four years of progress in Web browsers have given us more fancy presentation but almost no improvements in helping users navigate the Web and getting the information they need.

</div>

<div class="article-body">

<p>The release of version 4 of the leading Web browsers has been the cause of much celebration despite the fact that their <strong> support for user navigation is hardly better than Mosaic's </strong> (released 1993). Even though browsers have been substantially improved during the last four years, most of these improvements are aimed at serving media publishers: very few new features actually help users get around and manage their information needs better.</p>

<p>The architecture of most Web browsers bundles three levels of functionality:</p>

<ol>

<li>An <strong> Internet access layer </strong> with various protocols for communicating with remote websites, ranging from simple HTTP to various types of encryption and rating services (e.g., for avoiding pornography). The access layer has been improved substantially over the years: the keep-alive feature in HTTP 1.1 cuts load time in half for many pages; secure transmission of credit card numbers and other sensitive data helps people feel safe online. The continued lack of <a href="http://www.nngroup.com/articles/the-case-for-micropayments/" title="Alertbox Jan. 1998: Why micropayments are important for the growth of the Web"> micro-payments</a> is a major disappointment and impediment to the growth of quality Web services.</li>

<li>A <strong> navigation layer </strong> that keeps track of where users have been on the Web and helps them go where they want to go today. This layer has been sorely neglected and is the main topic of this column.</li>

<li>A <strong> presentation layer </strong> that takes a page from the navigation layer and renders it on the screen for users to enjoy. Most of the efforts in upgrading Web browsers have focused on this layer, introducing many options for fancy layout ranging from the annoying (animated GIFs) to the useful ( <a href="/articles/effective-use-of-style-sheets"> style sheets</a>).</li>

</ol>

<p>In my <a href="/articles/features-for-the-next-generation-of-web-browsers"> July 1995 Alertbox</a>, I called for several navigation features to be added to Web browsers:</p>

<ul>

<li>Better <strong> bookmark management</strong>. It has indeed gotten slightly easier to manage bookmarks: one can add a bookmark to a category instead of an endless list and users can see which bookmarked pages have changed since their last visit. Even so, bookmarks are still unreasonably difficult to use and do not provide sufficient support for users who visit a large number of sites.</li>

<li>Various facilities to leverage other users' behavior into <strong> quality ratings of links</strong>: still completely missing; current browsers think that all links are equal.</li>

<li>Overview diagrams of the user's <strong> navigation history</strong>. We can now sort the history list so that all the pages visited on a given site are listed together, but visualization is still missing. It would be very useful to have active sitemaps that showed the user's movements with footprints, showed additional detail at the current focus of attention while collapsing other regions, and also showed connections to other sites with a preview of the relevant sections of these other sites.</li>

<li><a href="/articles/features-missing-current-web-browsers-1995/">A list of 15 navigation features</a> that had been invented before 1995 but were not in Web browsers in 1995. Well, they still aren't.</li>

</ul>

<p>There have admittedly been some improvements, such as the ability to pop-down the history list from the Back button and the improved tooltip that tells you <em> where </em> the Back button will take you (the original tooltip that said something to the effect that "Back goes back" was as close to useless as I have ever seen in online help). <strong> Channels </strong> probably do count as a new navigation feature and can be seen as active fat bookmarks that allow users to monitor a larger scope than a single page at a time.</p>

</div><h2 id="toc-lack-of-structure-support-1">Lack of Structure Support</h2>

<p>Most of the problems with browser navigation can be traced to a single phenomenon: browsers still view individual <strong> pages as the fundamental units </strong> of navigation and have no support for treating multiple pages as a structure. Users are much more likely to get lost when they are not shown the relationships between the various pages they visit.</p>

<p><span style="font-size: 12px;">At a minimum, structure should be supported at the site level and the subsite level. For example, each site should have a name (typically the company name) that could be shown as a tooltip for links to pages within that site. Also, pages from the same region of a site (that is, a subsite) should be treated as a unit in history lists, bookmarks, searches, etc.</span></p>

<p>Showing search results in a sliding browser pane is a start that allows for weak <strong> integration between searching and browsing</strong>, but much tighter integration is needed. For example, if a page has a link to something that was on the search results list, then that link should be highlighted to indicate that it is related to the user's current interests. As another example, the search results list should highlight hits from sites that the user has visited in the past, since the user is likely to prefer those hits. This latter idea can be extended to vary the highlighting depending on the time the user has spent at the various sites (a site you use a lot would be shown more prominently than a site you use a little).</p>

<p>In general, page navigation must be integrated with value-added services retrieved from third-party servers. A current example (which is a clunky add-on and not truly integrated with the browser) is the Alexa where-to-go-next service which recommends other pages that are similar to the one the user is currently reading. A better example would be a <a href="http://www.nngroup.com/articles/the-reputation-manager/" title="Alertbox Feb. 1998: reputation management to guide users to Web quality"> reputation manager</a> that annotated each hypertext link with the quality of the destination as judged by other users who have the same taste as the current user.</p>

<h2 id="toc-how-you-can-improve-navigation-2">How You Can Improve Navigation</h2>

<p>Since browsers provide lousy navigation support, you need to go beyond the call of duty if you are a content designer. Websites need to include extensive navigation support to help users overcome the limitations of their software. Here are some things you can do yourself today:</p>

<ul>

<li>Include a <strong> site identifier on every page </strong> to let users know where they are relative to the Web as a whole. Usually, this takes the form of a corporate logo in the upper left corner of the screen (upper right if the site is in a language that reads right-to-left).</li>

<li>Make it <strong> easy to get to landmark pages</strong>: every page should be linked to the home page (typically by making the logo into a link) and to the <a href="/articles/search-and-you-may-find/"> search</a> page.</li>

<li><strong>Emphasize the structure </strong> of your information architecture: make every page show what <a href="/articles/the-rise-of-the-subsite"> subsite</a> (or other structural element) it belongs to and include a link to the overview page or main page for at least one level up in the structure. Such links should not have generic names like "go one level up" but should be specific and name the level they point to.</li>

<li><strong>Do not change the default link colors </strong> : links to unvisited pages should be some shade of blue and links to previously visited pages should be some shade of purple. Staying with shades of the default colors allows users to understand what parts of the site they have already seen: this helps them form a mental model of the site since they can relate the site structure to their personal navigation history.</li>

<li>Draw a <strong> <a class="old" href="http://www.useit.com/alertbox/20020106.html" title="Alertbox Jan. 2002: Site Map Usability"> sitemap</a>  </strong> that shows the most important levels of your information structure and the relations between different parts of the site.</li>

</ul>
