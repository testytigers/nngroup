<div class="article-summary article-heading-small-light">

<span class="article-summary-label">

Summary:&nbsp;

</span>Guest checkout with optional registration on e-commerce sites simplifies the purchase process and invites users to register when they feel comfortable, rather than forcing unwanted registration.

</div>

<div class="article-body">

<p>One of the most common complaints we hear in <a href="http://www.nngroup.com/reports/ecommerce-user-experience/">e-commerce usability research</a> is about registration. Shoppers have <strong>many reasons to dislike or dread site registration</strong>. They may <a href="http://www.nngroup.com/articles/ecommerce-shoppers/">not plan to return to the site again</a>, making a one-time purchase or a gift purchase. They may dislike registration in general, frustrated with remembering usernames and passwords for all the sites they visit. Some shoppers don’t want a site to save personal information and assume that if they register for the site, the information will be saved. Many users associate registration with getting unwanted email, and for good reason, since many sites offer tiny preselected checkboxes to sign up for email newsletters.</p>

<p>Most of all, registrations involves <strong>extra steps, extra hassle, and extra potential for things going wrong</strong> (whether user errors or site errors) and stopping the user dead in the water. The higher the <a href="http://www.nngroup.com/articles/interaction-cost-definition/">interaction cost</a>, the fewer people will complete a process. This is true for any user interface steps, but in the case of e-commerce checkout there’s a particularly direct connection between user hassle and lost sales.</p>

<figure class="caption"><img alt="" height="590" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/05/29/tinyprints_registration.png" width="720"/>

<figcaption><em>TinyPrints.com required that users create an account and also automatically subscribed users to the newsletter, mentioning above the Create Account button that “</em>You will be subscribed to the Tiny Prints email newsletter<em>” (stated in tiny print, which makes users weary right there.) Being signed up for newsletters they do not want is one of many complaints users have about registering on e-commerce sites.</em></figcaption>

</figure>

<p>Registration sounds like a tedious, lengthy process unrelated to the task at hand: making a purchase. And some sites make registration a lengthy and tedious process, sometimes even presenting registration as a step separate from the checkout process.</p>

<p>This doesn’t need to be the case. When a user is making a purchase, typically all the information needed for registration is already being requested of the user. Sites normally ask for information needed for the transaction, including name, shipping, and billing information. In addition, sites commonly ask for an email address in order to email a receipt and update order status. <strong>The only aspect of registration that is not covered in a standard checkout transaction is a password. </strong></p>

</div><h2 id="toc-how-to-present-optional-registration-1">How to Present Optional Registration</h2>

<ul>

<li>Before users enter the checkout process, <strong>clearly state that registration will be an option</strong>. Some users do want to register and like to see assurance that they can if they’d like to. If the option to create a password will be presented after the purchase is complete, rather than during the checkout process, tell users so they know when to expect the option.</li>

</ul>

<figure class="caption"><img alt="" height="392" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/05/29/homedepot_register.png" width="720"/>

<figcaption><em>Under the Guest Checkout option, HomeDepot.com told users that “</em>You will have the opportunity to create an account and track your order once you complete your purchase.<em>” The size of the text could have been larger to make it easier to read, though it is good to present this information less prominently than the main text.</em></figcaption>

</figure>

<ul>

<li>Briefly <strong>highlight the benefits of registration from the users’ perspective</strong> and not the company’s perspective when asking users to register. Shoppers appreciate when sites emphasize aspects that would make the experience easier, such as order tracking or faster checkout. They sometimes complain about sites that stress “benefits” such as receiving email newsletters or becoming a member of the site.</li>

</ul>

<p style="margin-left: 40px;">Mention customer-focused benefits when users start the checkout process as well as when customers are asked to create optional passwords. A brief bulleted list tends to work well to highlight this information. This list should not be a sales pitch for the site, but a brief reminder to users about how registering benefits them.</p>

<figure class="caption"><img alt="" height="529" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/05/29/nordstrom_register.png" width="720"/>

<figcaption><em>Nordstrom.com told users that registration would let them, “</em>Check out faster, Track your orders, Write reviews and more!<em>" This nicely presented the information as a benefit to the user, rather than the site.</em></figcaption>

<figcaption> </figcaption>

</figure>

<ul>

<li><strong>Mark password fields as optional</strong>, so it’s clear that users do not have to register for the site. Also make sure to <a href="http://www.nngroup.com/articles/password-creation/">state password requirements</a> so users aren’t left guessing how to create a valid password.</li>

</ul>

<p style="margin-left: 40px;">Some sites do not mark the password fields as optional; instead they place the fields in a section of the page with the word “optional” in a heading. Users often skim web content, even when filling in forms, and may miss the optional designation if it is only displayed in the heading, rather than next to the field.</p>

<p style="margin-left: 40px;">When the fields are not specifically marked, users can misinterpret it as a requirement for registration. If they were previously told that registration is optional or have pursued guest registration on the site, this inconsistency can break the user’s trust.</p>

<figure class="caption"><img alt="" height="289" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/05/29/staples_register.png" width="720"/>

<figcaption><em>Staples.com listed the optional passwords fields in a section titled </em>Optional Information<em>. That heading was in close proximity to the password fields, which only appeared if a user selected the </em>Create an account and make your next checkout easy option<em>. Both these factors helped reinforce that the fields were optional.</em></figcaption>

</figure>

<h2 id="toc-simple-and-optional-2">Simple and Optional</h2>

<p>Rather than forcing users to register before checking out, provide the option to register within the checkout process by presenting optional fields for the user to enter a password. This puts users in control and allows them to decide if it is worthwhile to register or not. In our <a href="http://www.nngroup.com/reports/ecommerce-user-experience/">e-commerce research</a>, we saw users who had previously complained about forced registration happily register for sites where registration was limited to the option of creating a password in the purchase process.</p>

<p>Forcing registration causes lost sales. Some users will leave the site, others will struggle with registration. It is common for sites that <strong>add guest checkout to immediately realize increased sales</strong>. It is a simple way to improve usability and encourage purchasing.</p>
