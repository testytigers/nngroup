<div class="article-summary article-heading-small-light">

<span class="article-summary-label">

Summary:&nbsp;

</span>iCab, a new web browser, uses the LINK tags from the page headers to provide additional navigation links to the users. This structural navigation provides a valuable alternative to users.

</div>

<div class="article-body">

<p><em>By Jakob Nielsen</em></p>

<p>iCab is a new Macintosh browser from Germany that introduces some interesting features to help users <strong> navigate the structure of a website</strong>. It is nice to see some competition to Internet Explorer: the Europeans have not given up innovating in Internet software, as also indicated by the Norwegian <a class="out" href="http://www.opera.no/" title="Opera Software: home page in English"> Opera</a> browser for Windows.</p>

<p>To give Microsoft credit where it's due, Internet Explorer is improving with every release. For example, version 5 finally introduces the ability to <strong> bookmark frames </strong> - "only" three and a half years after this <a class="old" href="/articles/why-frames-suck-most-of-the-time/" title="Alertbox Dec. 1996: Why Frames Suck"> abomination</a> was inflicted on the unsuspecting public. But much remains, so it's good to have alternative designs of Web browsers that do not come from the Mosaic tradition.</p>

<p>iCab uses the LINK tags from the page headers to provide additional navigation links to the users. The following screen shot shows an example of such links from one of my Alertbox columns.</p>

<p align="center"><img alt="Screenshot of iCab viewing an Alertbox page" height="176" loading="lazy" src="//media.nngroup.com/media/editor/2012/10/31/icabscreen.gif" width="698"/></p>

<p>The <strong> pop-up menu allows the user to navigate directly to pages that are related to the current page</strong>:</p>

<ol>

<li>The style sheet</li>

<li>The home page for the current website (useit)</li>

<li>The parent page to the current page (the list of all Alertboxes)</li>

<li>Sibling pages: the previous and next column in the chronological sequence of Alertbox columns</li>

</ol>

<p>I would have preferred a design that didn't show the style sheet, since no normal user will want to view the CSS code that defines the presentation of the page. Also, I would have preferred a design that used the REL (relation) attribute in the LINK tag to name the structural links. For example, it would have been better to explicitly state that the link I named "List of all Alertbox columns" is the parent (i.e., one level up in the information architecture). Of course, I try to use good link names, but many Web authors pay less attention to <a class="old" href="/articles/microcontent-how-to-write-headlines-page-titles-and-subject-lines/" title="Alertbox Sept. 1998: Microcontent: How to Write Headlines, Page Titles, and Subject Lines"> micro-content</a>, so users may need to have the links explained.</p>

<p>The small buttons above the link menu are used for structural navigation, so users have one-click access to the most important related pages, making the issue of named menu items less critical.</p>

<p>The great breakthrough in the iCab link menu and navigation buttons is the introduction of <strong> structural navigation </strong> to Web browsing. There is now a standardized way for users to get to higher levels of the information architecture and to pages that have specific relationships to the current page. In other words, the user interface is being liberated from the narrowing confines of single-page viewing and moved into the more appropriate direction of navigation support. With structure navigation standardized in the browser, users will be less lost in the future and the Web pages themselves can focus more on content.</p>

<p>(Keith Instone points out that iCab lists LINK tags in the sequence in which they appear in the page HEAD. This is a reason to think carefully about the sequence and make sure that the LINKs appear in a logical order with the most important ones first.)</p>
