<span class="article-summary-label">

Summary:&nbsp;

</span>For users who can’t use a mouse make interactive and navigation elements easily accessible by tabbing and display a keyboard-focus indicator.

</div>

<div class="article-body">

<p>Certain users navigate the internet <strong>using the keyboard rather than the mouse</strong>. Expert “power” users prefer keyboard commands for efficiency, while users with certain disabilities have no choice but to use the keyboard. For example, people with a <strong>motor impairment</strong> have difficulty with the fine motor movements required for using a mouse; <strong>blind</strong> users rely on assistive technology such as screen readers and can’t see where to click the mouse.</p>

<p>The big difference between the keyboard and the mouse is that when users navigate through the keyboard, the access to the links on the screen is <strong>sequential</strong>: users must tab through all the links one by one before reaching a link of interest.  In contrast, a mouse user can inspect the links available on the screen and move the cursor directly to the link he wants to click; thus, the mouse allows <strong>direct access</strong> to the links on the screen.</p>

<p>Even the most fancy or wonderful site is completely useless to someone who cannot access its controls and interact with it.  Keyboard-friendly websites make these interactions possible for users who cannot use the mouse.</p>

</div><h2 id="toc-test-a-websites-keyboard-accessibility-1">Test a Website’s Keyboard Accessibility</h2>

<p>For those of you reading this article on a desktop or laptop in Firefox, IE, Chrome, or Safari, please do this exercise.</p>

<ol>

<li>Click in the browser address bar.</li>

<li>Take your hand off your mouse and use only your keyboard.</li>

<li>Using the <em>Tab</em> button, navigate until you’ve reached the link below. (You can use <em>Shift+Tab</em> to navigate back one step.)</li>

</ol>

<p style="margin-left:120px"><a href="#">Test Link, Doesn't Go Anywhere</a></p>

<p> </p>

<p>You probably noticed 4 things:</p>

<ol>

<li>You could follow along with where the keyboard focus was on the page.</li>

<li>You were able to select any link on the page.</li>

<li>Tabbing followed the same order as the page layout: left to right and top to bottom in columns.</li>

<li>It was a bit annoying to tab through the long navigation lists before getting to the test button. (But you could do it.)</li>

</ol>

<p>This is a quick test to run on your website as well. When you do the test, follow the next 3 guidelines for making your website keyboard accessible.</p>

<h2 id="toc-obvious-keyboard-focus-2">Obvious Keyboard Focus</h2>

<p>Imagine someone using their mouse to browse the internet without seeing the cursor on the screen. Impossible, right? This is what it’s like if there’s no visual indicator of where the keyboard focus currently is on the page.</p>

<p>Websites need to provide the same feedback for keyboard and mouse users. The keyboard focus is coded by default into all the common web browsers. Some browsers default to a thin grey dotted line, others to a blue solid border. (This difference doesn’t matter: users will know the convention employed by their favorite browser.)</p>

<p>Removing the keyboard focus indicator is catastrophic for keyboard users. Commonly, the focus indicator is removed because it’s thought to be an eye sore. If you don’t like the indicator provided by the browser, don’t remove it altogether; instead replace it with a design that is consistent with your site’s look-and-feel. This <a href="https://css-tricks.com/almanac/properties/o/outline/">CSS tutorial on how to add in a new focus style</a> might be helpful.</p>

<figcaption><em>MailChimp.com uses the default browser visual focus. In the above example, viewed in IE11, it is clear that the user is on the link 'Email Designer.' Hitting </em>Enter <em>would take them to that page.</em></figcaption>

</figure>

<p> </p>

<figure class="caption" style="float:left"><img alt="StrideHealth homepage with 4 main navigation menu items and visual focus on the first one, Find Your Plan" height="346" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/04/10/stridehealth_visual-focus_callout.jpg" width="722"/>

<figcaption><em>StrideHealth.com replaced the default visual focus with the hover-state design: Tabbing through the main navigation in the top right with a keyboard looks the same as when hovering over each item with a mouse. It is very clear that the user is currently on </em>Find Your Plan<em>.</em></figcaption>

</figure>

<p> </p>

<h2 id="toc-all-interactive-elements-are-accessible-3">All Interactive Elements Are Accessible</h2>

<p>Keyboard users must be able to access all interactive elements, not just the main navigation or in-line links. This means that form elements, drop-down menus, buttons, dialog boxes, and other widgets all have to be accessible by tabbing through the interface.</p>

<p>The biggest problem is caused by JavaScript widgets with &lt;div&gt; or &lt;span&gt; elements. These can be <a href="https://developer.mozilla.org/en-US/docs/Web/Accessibility/Keyboard-navigable_JavaScript_widgets">assigned keyboard focus through tabindex.</a> Alternatively, using only HTML links, buttons, and form fields will ensure that all elements can be tabbed to.</p>

<figure class="caption" style="float:left"><img alt="SF Zoo Tickets Form with keyboard insertion point in the First Name field" height="415" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/04/03/sf-zoo-ticket-form_callout.jpg" width="720"/>

<figcaption><em>The San Francisco Zoo ticket-request form is keyboard accessible. In the screenshot above the keyboard focus is on the </em>First Name<em> field. Hitting the </em>Tab <em>key moves the focus to </em>Last Name<em>, allowing all users to complete and submit this form.</em></figcaption>

</figure>

<p> </p>

<figure class="caption" style="float:left"><img alt="Bed Bath and Beyond homepage with large centerpiece carousel and dotted, visual focus, line around the second chapter indicator" height="392" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/04/03/bedbathbeyond-carousel_callout.jpg" width="722"/>

<figcaption><em>A common problem is that media controls, such as those in carousels, are not keyboard accessible. However, on Bed, Bath, and Beyond you can tab to each chapter indicator and hit </em>Enter <em>to view that carousel chapter. (Note that this <a href="http://www.nngroup.com/articles/designing-effective-carousels/">carousel would be more effective with recognizable icons</a> or thumbnail images, instead of dots.)</em></figcaption>

</figure>

<p> </p>

<figure class="caption" style="float:left"><img alt="Feedback pop up on FDA For Professionals page" height="614" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/04/03/fda-pop-up_callout.jpg" width="720"/>

<figcaption><em>FDA.gov follows through with keyboard accessibility by making it possible to navigate to and out of pop-ups. It is extremely important for users to be able to close pop-ups or they will be stuck inside them.</em></figcaption>

</figure>

<p> </p>

<p>Drop-down menus can be difficult to use by keyboard if users can’t scroll through the list separately from making a selection. This happens if the arrow-down button selects the first item from the list, instead of moving down through the list options. For example, in the dropdown below this would result in selecting <em>Apples</em> when hitting the arrow-down key once. Instead, the arrow-down key should let the user scroll between <em>Apples</em>, <em>Bananas</em>, and <em>Oranges</em> and use <em>Enter</em> to make their selection. </p>

<p style="text-align:center"><img alt="Sketch of expanded drop-down menu with options Apples, Bananas, and Oranges" height="104" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/04/03/dropdown.png" width="127"/></p>

<p> </p>

<figure class="caption" style="float:left"><img alt="Overview page on Ted.com with 4 drop-down menu filters, with the Events filter expanded and TedGlobal 2013 highlighted" height="348" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/04/03/ted_dropdown_callout.png" width="720"/>

<figcaption><em>The drop-down list on Ted.com works well by keyboard. Users can tab to their filter of choice, here </em>Events<em>, then hit </em>Enter <em>which brings them inside the drop-down. Then the arrow keys work to select their item, and another </em>Enter <em>makes their selection.</em></figcaption>

</figure>

<h2 id="toc-consider-a-skip-navigation-link-4">Consider a <em>Skip Navigation</em> Link</h2>

<p>On most websites the tab order will be coded to reflect the page layout; that is top to bottom and left to right. This helps sighted keyboard users get around the page.</p>

<figure class="caption" style="float:left"><img alt="City of London homepage with numbered arrows indicating the flow of tabbing from left to right and top to bottom" height="708" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/04/03/city-of-london-tab-order.png" width="720"/>

<figcaption><em>The </em>Tab <em>order on the City of London website follows the same visual flow as the page layout. The red numbered circles indicate the order and direction of tabbing through the page.</em></figcaption>

</figure>

<p> </p>

<p>One of the pitfalls of tabbing along the page layout is that navigation comes first in the conventional webpage layout (which we strongly recommend retaining to <a href="http://www.nngroup.com/articles/the-need-for-web-design-standards">leverage user expectations</a>). On some pages that means that keyboard users might have to tab through 100+ navigation elements to get to the main content, which can be difficult (let alone time consuming).</p>

<p>Mouse users can simply disregard the main navigation and interact directly with any of the links in the main content area. Offering a <a href="http://webaim.org/techniques/skipnav/"><em>Skip Navigation</em> link</a> provides some of that benefit to keyboard-only users.</p>

<figure class="caption"><img alt="Government of Canada Skip to main content link in the top left corner" height="605" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/04/10/gov-canada-skip-to-main-content-callout.png" width="722"/>

<figcaption><em>The Government of Canada website offers a </em>Skip to main content<em> link at the top of the page. This link only becomes available when users tab through the page, so it doesn’t disturb the visual design for mouse users. The link name is descriptive and concise. Hitting </em>Enter <em>on the </em>Skip Navigation <em>link takes users to the page heading </em>Immigration &amp; citizenship<em>, allowing them to continue tabbing through the links in the body content on the page. This last step is frequently overlooked, but essential. </em></figcaption>

</figure>

<h2 id="toc-conclusion-5">Conclusion</h2>

<p>People who are unable to use a mouse or see the screen need to access all website content and functionality through their keyboard alone. To make your website keyboard accessible it is important to allow users to: 1) follow along with where the keyboard focus is, 2) navigate to all interactive elements, and 3) bypass the navigation if there are many links.</p>
