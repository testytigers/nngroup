<div class="article-summary article-heading-small-light">

<span class="article-summary-label">

Summary:&nbsp;

</span>People usually recognize that a magnifying-glass icon indicates a search tool, even when it has no label. Unfortunately, showing only the icon makes search more difficult to find.

</div>

<div class="article-body">

<p>In doing research to update our course on <a href="https://www.nngroup.com/courses/emerging-patterns-web-design/">Emerging Patterns in Web Design</a>, we looked more closely at what’s happening with search boxes. Many designs are swapping the traditional <strong>button labeled “Search”</strong> with a <strong>magnifying-glass icon</strong> without any label. Some even drop the text field entirely, leaving only the icon. Which version is most usable today?</p>

</div><h2 id="toc-previous-guidelines-about-the-search-box-1">Previous Guidelines About the Search Box</h2>

<p>Our <a href="https://www.nngroup.com/articles/search-visible-and-simple/">guidelines around the search field</a> have remained the same for many years. (See the updated full list of <a href="https://www.nngroup.com/reports/ecommerce-ux-search-including-faceted-search/">62 design recommendations for search</a>). Regarding presentation, the main guidelines are:</p>

<ul>

<li>Provide an easily identifiable search box in the upper right-hand corner of the page, with an open text-field accompanied by a <em>Search</em> button.</li>

<li>The search box needs no label. A <em>Search</em> button next to the field identifies the search for the user and tells them how to execute the search.</li>

</ul>

<p>And yet, some patterns emerging today break these fundamental guidelines. The magnifying-glass icon saves space, so more websites use it. It’s OK to be flexible with previous guidelines, so long as we acknowledge that the users’ needs remain unchanged. People don’t care what the search area looks like: they just want a place where they can quickly go to type in their search query. If design conventions are changing, but still allow users to accomplish that goal easily without slowing them down, then there shouldn’t be a problem. As we’ll see from our findings though, icon-only search has some significant disadvantages.</p>

<figure class="caption"><img alt="5 examples of search tools showing variations in buttons and icons in recent years" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/02/14/search_evolution__.png" style="width: 400px; height: 291px;"/>

<figcaption><em>(a): Traditional search box with </em>Search<em> button; (b, c, d): Emerging search box patterns with magnifying glass icon; (e): Mobile-influenced pattern of icon-only search with no open text field. (We recommend against this last design.)</em></figcaption>

</figure>

<h2 id="toc-adoption-of-an-icon-2">Adoption of an Icon</h2>

<p>The magnifying glass has become associated with search partly because so many different websites, applications, and operating systems have been using it dependably as a way to find information.</p>

<p>With such consistent implementation, people have learned to recognize this icon more quickly. The icon-only pattern became especially popular with the emergence of responsive design (though <a href="https://www.nngroup.com/courses/scaling-responsive-design/" title="Scaling User Interfaces: Usability for Responsive Web Design and Other Approaches to Designing Websites for Multiple Devices - full-day training course">good responsive sites</a> show a search box with the icon when transitioning to larger screens).</p>

<figure class="caption"><img alt="Search tools used in applications, showing variations in magnifying glass icon placement" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/02/14/search_crossapplication_.png" style="width: 400px; height: 245px;"/>

<figcaption><em>The magnifying-glass icon used for search in various applications and operating systems has contributed to user’s familiarity with and expectations about the icon. From top to bottom: Google Chrome, Windows Explorer, Internet Explorer, and Microsoft Word for Mac.</em></figcaption>

</figure>

<h2 id="toc-findings-from-our-recent-research-3">Findings from Our Recent Research</h2>

<p>Our recent user-research findings show that the transition to the search icon is not as smooth and without perils as designers may want. Here are some difficulties that people encounter with this new search-icon pattern.</p>

<h3>The magnifying glass alone makes it much harder to locate the search.</h3>

<p>When used without an open-entry text field, the icon takes up less space. Visually, it’s less prominent and, therefore, less noticeable. We don’t recommend the icon-only pattern for desktop websites. Icon-only search makes sense on mobile devices, because there’s less screen space and fewer icons and labels in general. But on desktop, there’s more to look at, and thus, it’s easier for the stand-alone search icon to get lost in the crowd.</p>

<h3>Users understand the icon enough that, when styled appropriately, spelling out the word “Search” as a label is no longer required.</h3>

<p>Most people in our recent studies recognize and understand the function of the magnifying glass. They notice it and associate it with search. If the icon is obvious and has a strong enough affordance that it’s clickable, a separate button labeled “Search” isn’t necessary. <strong>Because many users still have the habit of clicking a <em>Search</em> button to submit the query, it’s essential that clicking the magnifying glass submit the query</strong>. As an added benefit for sites with <a href="https://www.nngroup.com/topic/international-users/">international versions</a>, there is no need to translate "Search" when using the icon in place of a button. (However, for <a href="https://www.nngroup.com/topic/accessibility">accessibility</a> reasons, remember to include the word “search” or its translation as an ALT text for any graphics-only button.)</p>

<h3>When search is placed in an unexpected location, people need extra help to find it.</h3>

<p>People first look to the upper-right corner for search. If they don’t find it there, they start scanning the top of the page. Among sites that had the search icon on the left, those that used a large, empty open-text field fared best with our users. Although people eventually found the search box, they shouldn’t have had to scour the page for it in the first place.</p>

<h3>Icon-only search increases the <a href="https://www.nngroup.com/articles/interaction-cost-definition/">cost of interaction</a>.</h3>

<p>A downside to having only an icon for search means that the user has to wait for a search box to appear, find where to start typing, and sometimes click one more time to focus on the input field. These additional steps prolong the search process, where it would have been much faster to simply click in the text field and start typing immediately.</p>

<h3>Most other icons still require labels for clarity.</h3>

<p>Icon labels help people make decisions faster: they give good <a href="https://www.nngroup.com/articles/wrong-information-scent-costs-sales/">information scent</a> about what will come next. Labels should still be used for newer icons, such as the <a href="https://www.nngroup.com/articles/hamburger-menus/">three-line menu (hamburger) icon</a>. The map-marker icon is another icon with a still cloudy meaning and inconsistent use. Sometimes it means current location, or a different particular location, or locations in general, or nearby places.</p>

<figure class="caption"><img alt="Three-line menu and map-marker icons" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/02/14/menu_and_mapmarker_icons_.png" style="width: 103px; height: 54px;"/>

<figcaption><em>People are still largely unfamiliar with newer icons, including the three-line menu icon (left) and the map-marker icon (right).</em></figcaption>

</figure>

<p>Users are still learning what these icons mean and how they behave, so it’s best to use a label. Besides, there’s enough room on desktop screens, so why not make it easier and faster for people to find what they’re looking for?</p>

<h2 id="toc-recommendations-for-designing-with-the-magnifying-glass-icon-4">Recommendations for Designing with the Magnifying-Glass Icon</h2>

<ol>

<li>Above all, <strong>retain an open text-entry field</strong> next to the icon in the desktop version of a website. It’s also best to retain the text field on <a href="https://www.nngroup.com/reports/tablets/">tablets</a>. When a site is viewed on small screens (such as those of smartphones and smartwatches), the text box can be hidden until the user touches the magnifying-glass icon. And in each of these cases, there is no need to include a label within the search box.</li>

<li>Use a <strong>schematic icon</strong>, the simplest version of the magnifying glass. Fewer graphic details speed up recognition.<br/>

<img alt="Schematic magnifying-glass icon" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/02/14/search_bw-icon.png" style="width: 40px; height: 40px;"/> <em>instead of</em> <img alt="Non-schematic magnifying-glass icon" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/02/14/search_not-schematic.png" style="width: 40px; height: 40px;"/></li>

<li>Use a large icon with lots of padding. A larger clickable area makes it easier to spot and to click.<br/>

<img alt="Large search icon" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/02/14/search_gmail-icon.png" style="width: 195px; height: 37px;"/> <em>instead of</em> <img alt="Small search icon" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/02/14/search_small-icon_.png" style="width: 230px; height: 38px;"/></li>

<li>Use plenty of <strong>contrast</strong> so that the icon stands out from the background and from the surrounding elements.</li>

<li>Place the search tool in the <strong>upper-right corner</strong>, which is still the first place people expect to find search.</li>

<li>Let users <strong>submit search</strong> using the <em>Enter</em> key <em>and</em> by clicking the icon. I mentioned this above, but it’s worth reiterating: many people still have the habit of clicking an actual button to submit search.</li>

<li>Consider using a <strong>growing search box</strong>, which expands the text input field on click. This saves screen space while still giving the user enough visual cues to quickly find and execute search. If the box is a fixed size, <a href="https://www.nngroup.com/articles/top-ten-guidelines-for-homepage-usability/">we recommend making the text-entry area at least 27 characters wide</a>, so people can easily see their queries and correct spelling without having to scroll the text in the box.

<figure class="caption"><img alt="Growing search box" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/02/14/search_growing_.jpg" style="width: 400px; height: 116px;"/>

<figcaption><em>Top: Search box before clicking the text field. Bottom: After clicking, search box expands.</em></figcaption>

</figure>

</li>

</ol>

<p><strong><em>Recommendations 8-11 apply if you are using the icon without the text input field:</em></strong></p>

<ol start="8">

<li><strong>Don’t crowd the surrounding area</strong> with other icons that might distract from it. Give search the priority it deserves.<br/>

<img alt="Search icon crowded by icons" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/02/14/search_blends-into-icons.png" style="width: 195px; height: 45px;"/></li>

<li>The reverse of the previous guideline: <strong>don’t isolate </strong>the search, which can make it just as difficult to find as crowding it.<br/>

<img alt="Isolated search icon" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/02/14/search_isolated.png" style="width: 400px; height: 66px;"/></li>

<li>When users click on the search icon, <strong>display the text-entry field close</strong> to that icon. Placing it far away increases the interaction cost for the user by forcing them to find the box before they can start typing. It also goes against the <a href="https://www.nngroup.com/articles/form-design-white-space/">Gestalt law of proximity</a> to show related items far from each other.<br/>

<img alt="Search box too far from icon" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2014/02/14/search_faraway.jpg" style="width: 639px; height: 257px;"/></li>

<li><strong>Don’t make people click twice</strong> when once (or not at all) will do. In some cases, the user has to first click the icon to open the search box and then click to move the input focus into the search field. One click on the icon should put the cursor in the field, ready for typing. Better yet, expand the search field <em>on hover</em>, with the cursor ready for input.</li>

</ol>

<h2 id="toc-the-goal-is-to-help-people-find-and-execute-search-quickly-5">The Goal is to Help People Find and Execute Search Quickly</h2>

<p>If your website uses a magnifying-glass icon instead of a search button on desktop, the recommendations here should help. At NN/g, we’re still using the search button on our website. We have the space, and we have no doubt that people can spot search on our site. We’ll also keep an eye on other emerging patterns regarding search, such as placement on the left, and use of voice command.</p>
