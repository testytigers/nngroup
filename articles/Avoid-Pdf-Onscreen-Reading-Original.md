<div class="article-summary article-heading-small-light">

<span class="article-summary-label">

Summary:&nbsp;

</span>Forcing users to browse PDF files makes usability approximately 300% worse compared to HTML pages. Only use PDF for documents that users are likely to print. In those cases, following six basic guidelines will minimize usability problems.

</div>

<div class="article-body">

<p>PDF is great for distributing documents that need to be printed. But that is all it's good for. No matter how tempting it might be, you should never use PDF for content that you expect users to read online.</p>

<p>Forcing users to <strong> browse PDF documents makes your website's usability about 300% worse </strong> relative to HTML pages. This is my rough estimate, based on watching users perform similar tasks on a variety of sites that used either PDF or regular Web pages. Because I have not performed a detailed measurement study of PDF on its own, I can't calculate the precise usability degradation. However, whether the true number is 280% or 320%, one thing is certain: the number is big and reflects significant user suffering in terms of increased task time and more frequent failures.</p>

</div><h2 id="toc-problems-with-pdf-1">Problems with PDF</h2>

<p>PDF was designed to specify printable pages. PDF content is thus optimized for letter-sized sheets of paper, not for display in a browser window. I often see users getting <strong> lost in PDF </strong> because the print-oriented viewer gives them only a small peephole on a big, complicated layout and they can't scroll it in the simple, linear manner they are accustomed to on the Web. Instead, PDF files often use elaborate graphic layouts and split the content into separate units for each sheet of print. Although this is highly appropriate for printed documents, it causes severe usability problems online.</p>

<p>PDF pages <strong> lack navigation bars </strong> and other apparatus that might help users move within the information space and relate to the rest of the site. Because PDF documents can be very big, the inability to easily navigate them takes a toll on users. PDF documents also typically lack hypertext, again because they are designed with print in mind.</p>

<p>In a recent study of <a class="old" href="/articles/corporate-websites-get-a-d-in-pr/" title="Alertbox April 2001: Corporate websites get a 'D' in PR"> how journalists use the Web</a>, we found that PDF files sometimes <strong> crashed the user's computer</strong>. This happened most often to journalists working from home on low-end computers (especially old Macs). The more fancy the company's press kit, the less likely it would get quoted.</p>

<p>Because PDF is not the standard Web page format, it dumps users into a non-standard user interface. Deviating from the norm hurts usability because, for example, scrolling works differently, as do certain commands, such as the one to make text larger (or smaller). Also, after finishing with a PDF document, users sometimes close the window instead of clicking the Back button, thus losing their navigation history. Although this behavior is not common, it is symptomatic of the problems caused when you present users with a non-standard Web page that both looks different and follows different rules.</p>

<h2 id="toc-guidelines-for-using-pdf-2">Guidelines for Using PDF</h2>

<p>You should use PDF only for documents that users need to download and print. Which documents fall in this category? Anything with <strong> five pages or more </strong> is a good candidate, since users <a class="old" href="/articles/how-users-read-on-the-web/" title="Alertbox Oct. 1997: How users read on the Web"> don't want to read a lot of text on the screen</a>.</p>

<p>Usually, it's best to break up a long, linear document into multiple hypertext pages so that you avoid having a fat report in the first place. Sometimes big documents are needed, however, either because you have a lot of content or prefer a linear presentation. Classic examples of this are textbooks and manuals.</p>

<p>Sometimes it even makes sense to create a single PDF document that unifies multiple Web pages into a single printable download. If users typically need all of the information in a single session, they might <a class="old" href="/articles/in-defense-of-print/" title="Alertbox Feb. 1996: In Defense of Print"> prefer to print it out</a>.</p>

<p>When you make a PDF document available for download, follow these <strong> guidelines</strong>:</p>

<ul>

<li><strong>Create a gateway HTML page that summarizes the PDF file </strong> in sufficient detail, including page count and file size. This will let users decide whether it is worth downloading.</li>

<li><strong>State clearly that the PDF file is for printing only</strong>. Present the same content on other Web pages in traditional formats, and provide links to them for readers who prefer to read online.</li>

<li>From any other part of the website,<a href="http://www.nngroup.com/articles/gateway-pages-prevent-pdf-shock/"> <strong> link only to the gateway page</strong></a>, not to the PDF document.</li>

<li><strong>Never let your search engines index the PDF file</strong>. Instead, ensure that your gateway page is indexed. Even though PDF files typically contain secondary background material, I've often seen them come up high in search result listings (possibly because big files are likely to contain multiple occurrences of query terms). In any case, usability suffers when users are unceremoniously dumped into a PDF file, especially if it's one that merely mentions their query in passing on page 47.</li>

<li>Ensure that your <strong> PDF document format is at least one version behind </strong> the latest offering. As with any Internet software, many <a class="old" href="/articles/the-increasing-conservatism-of-web-users/" title="Alertbox March 1998: The Increasing Conservatism of Web Users"> users are slow to upgrade </a> when new formats ship. PDF version 5 was released recently, but I recommend sticking to version 3 until 2002 (at which time you can use version 4; version 5 should not be used until 2004). I got many complaints when I made my <a class="old" href="http://www.nngroup.com/reports/ecommerce/" title="Design Guidelines for E-Commerce User Experience - Report series for download"> 207 usability guidelines for ecommerce </a> available for download in PDF 4 format recently: even among Internet professionals, there are still many people who have Acrobat version 3 installed on their machine. I am now wiser and will be keep using PDF 3 for any printable reports I publish in 2001.</li>

<li><strong>Format your printable documents for different sizes of paper</strong>. Some countries use 8.5x11, while others use A4. Make sure your document will fit both.</li>

</ul>

<h2 id="toc-update-2003-pdf-still-causing-trouble-3">Update 2003: PDF Still Causing Trouble</h2>

<p>Two recent studies once again found severe usability problems when users were dumped directly into PDF files for online reading:</p>

<ul>

<li><a class="new" href="http://www.nngroup.com/articles/intranet-usability-huge-advances/" title="Alertbox Nov. 2002: Intranet Usability: The Trillion-Dollar Question">Intranet usability</a>, especially relating to employee handbooks that need to be broken down into focused Web pages instead of being thrown online as a single blob in PDF format.</li>

<li><a class="new" href="http://www.nngroup.com/articles/investor-relations-ir/" title="Alertbox Feb. 2003: Investor Relations Website Design">Investor relations</a> information on corporate websites. Even though it is good to be able to download and print out annual reports, financial information for online reading must be provided in simpler formats that are easier to navigate.</li>

</ul>

<p>See Alertbox for July 2003 for <a class="new" href="/articles/pdf-unfit-for-human-consumption/" title="Alertbox: PDF - Unfit for Human Consumption"> quotes from user testing of websites and intranets with PDF</a>.</p>
