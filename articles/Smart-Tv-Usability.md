<div class="article-summary article-heading-small-light">

<span class="article-summary-label">

Summary:&nbsp;

</span>UX design for television UIs should focus on minimizing user effort and providing quick and smooth access to content.

</div>

<div class="article-body">

<p>When it comes to television service, we’ve got our choice of cable-TV providers, satellite-TV providers, online media-streaming services, and more. With all of these options there is always an ongoing discussion about which service is the “best” for various reasons. When thinking about what sets them all apart, one important comparison should include the television-watching experience and the TV interface itself.</p>

<p>Regardless of the TV service you subscribe to, you were most likely given a remote control that can be used to access and interact with the provided TV user interface. With extras like DVR functionality being offered by many services, modern TV interfaces must support fairly complex interactions around recording content. That said, the primary purpose of the interface should be to enable users to watch the TV programs that they want.</p>

<p>In this article we discuss the overarching principles that must be considered to address the top user tasks in this domain: browsing, locating, and accessing television programs.</p>

</div><h2 id="toc-minimize-button-clicks-on-the-remote-1">Minimize Button Clicks on the Remote</h2>

<p>Modern <a href="/articles/remote-control-anarchy/">remote controls are cumbersome and nonstandard devices, inconsistent</a> across the multiple pieces of consumer electronics in the modern home. With current smart TVs that display a set of onscreen choices, people need to use the remote’s four directional arrow buttons to position the cursor on the desired item and then confirm the selection by pressing the <em>Select</em> button on the remote.</p>

<p>Moving through a TV interface and making selections with the remote can be an intensive process. Unlike with a mouse, moving on a TV screen with a remote is a discrete process that involves going through all the clickable screen elements that happen to be on the path to an object of interest. The average selection will thus incur a significantly larger <a href="/articles/interaction-cost-definition/">interaction cost</a>, so it’s important to minimize the amount of selections needed to achieve a task.</p>

<p>The Google Fiber television service (a fast broadband plus TV service available in a few areas of the US) has this problem in the <em>On Demand</em> movie-selection screens. It uses <a href="/articles/windows-8-disappointing-usability/">Windows-8</a>-style tiles for content selection. This tile layout does not lend itself well to browsing the entire set of options. The tiles are scrollable horizontally, so in order to view the next set of movies, the user must click the right arrow on the remote through all 5 tiles in a row before being able to move to the next page. For example, to see all of the 500 movies that are offered <em>On Demand </em>(see the screenshot below), users had to click the right arrow <strong>245 times</strong> (5 times to advance to each new 10-channel page.) One user with whom I spoke bemoaned the effort of arrowing through each option and said he would have preferred to be able to page through the content. If one-click horizontal paging were supported to browse this content, the user would “only” have to click 49 times to view all of the movies.</p>

<div style="text-align:center">

<figure class="caption" style="display:inline-block"><img alt="Google Fiber Movies" border="0" height="398" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/09/15/googlefiber-movies.png" width="720"/>

<figcaption><em>Google Fiber‘s </em>On Demand<em> movie-selection page showed horizontally scrollable tiles and required 5 clicks to advance to the next set of movies. Viewing the entire set of available movies was an intensive process, likely reserved only for the most committed viewers.</em></figcaption>

</figure>

</div>

<p>The screen does provide a more advanced way to view options. The <em>ABC</em> button at the top (see screenshot above) opens a small alphabetical menu. Since the movies are already arranged alphabetically, selecting each letter creates somewhat of a “fast forward” effect, taking the user directly to the beginning of the options that start with that letter. While this design works if you know exactly what movie you want to see, it’s a <a href="/articles/alphabetical-sorting-must-mostly-die/">bad solution for those looking to browse</a> options.</p>

<h2 id="toc-dont-obscure-content-2">Don’t Obscure Content</h2>

<p>When it comes down to it, the TV interface is not the “star of the show.” The <strong>TV program itself is what’s important</strong> to users, and the interface is simply a tool to help them access it. The interface should be as minimally invasive as possible, and should not obscure programming content unnecessarily.</p>

<p>AT&amp;T U-verse shows navigation menus by way of a transparent overlay atop the background programming. The overlay allows users to continue viewing the content in the background while they navigate the interface. This feature can be nice sometimes, but when the background programming displays text, the interface becomes difficult to read.</p>

<div style="text-align:center">

<figure class="caption" style="display:inline-block"><img alt="AT&amp;T U-Verse Record menu" border="0" height="412" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/09/15/attuverse-overlay.png" width="720"/>

<figcaption><em>AT&amp;T U-verse interface displayed a transparent overlay on top of the program currently being watched. This caused difficulties when the background content contained text.</em></figcaption>

</figure>

</div>

<p>Google Fiber’s interface does not obscure content until it is necessary. The top level of the menu, triggered by pressing the key <em>Menu</em> on the remote, is slim and occupies little screen space, displaying only the main top-level navigation categories. As a result, users who accidentally expose the menu will not get their TV-viewing experience interrupted by a complex navigation display. Once users have shown their commitment to navigation by pressing one of the main-menu categories, the menu options are displayed on the whole screen.</p>

<div style="text-align:center">

<figure class="caption" style="display:inline-block"><img alt="Google Fiber TV Menu" border="0" height="415" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/09/15/googlefiber-menu.png" width="720"/>

<figcaption><em>Google Fiber’s main navigation menu appeared at the bottom of the screen. We will still see if the batter strikes out.</em></figcaption>

</figure>

</div>

<p>After the user has committed to the navigation menu, the programming content is obscured by a full-screen interface, but the current program is still displayed in a small thumbnail at the top right corner of the screen, allowing users to give attention to the program while also using the interface.</p>

<div style="text-align:center">

<figure class="caption" style="display:inline-block"><img alt="Google Fiber Program Thumbnail" border="0" height="411" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/09/15/googlefiber-programthumbnail.png" width="720"/>

<figcaption><em>Google Fiber’s interface put primary focus on the navigation while showing the current program in the top right corner. Content is obscured but still provided in sufficient degree to allow viewers to demine if something is happening in the live video that they want to watch.</em></figcaption>

</figure>

</div>

<h2 id="toc-provide-appropriate-visual-hierarchy-and-navigational-cues-3">Provide Appropriate Visual Hierarchy and Navigational Cues</h2>

<p>Some services offer thousands of channels and <em>On Demand</em> programs. All this content can be organized into complex organizational structures involving many levels of categories and subcategories. That being the case, it’s incredibly important that these architectures be intuitive and provide the proper navigational cues to prevent the user from feeling lost in the interface.</p>

<p>(Of course, <a href="/topic/information-architecture/">good IA</a> is always important, but it becomes crucial when users are not provided with a powerful user interface that they can easily and forcefully manipulate.)</p>

<p>Time Warner Cable’s channel-browsing feature creates this problem with its placement of menus. When the user selects the <em">Live TV category, the list of different subcategories (<em>Entertainment, Movies &amp; Premiums,</em> etc.) is displayed on the screen and the overarching category (<em>Live TV</em>) is shown below it. This layout breaks the convention of showing the categories in a logical top–down visual hierarchy. When the user chooses a subcategory such as <em>News and Info,</em> the screen adjusts: the overarching-category label <em>Live TV</em> moves to the top of the page. The selected subcategory <em">News and Info moves to the menu at the bottom of the page, and the underlying channel selections (<em>Al Jazeera, BBC World News,</em> etc.) are then shown in the center. With such a split layout of categories, it’s hard for users to quickly understand the information hierarchy of the system and where they are in it.</em"></em"></p>

<div style="text-align:center">

<figure class="caption" style="display:inline-block"><img alt="Time Warner Cable channel browsing" border="0" height="829" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/09/15/timewarnercable-flow.png" width="720"/>

<figcaption><em>Time Warner Cable’s channel-browsing feature split the information hierarchy across different sections of the screen: the level immediately above the content was shown at the bottom of the screen, and, if an even higher level was available (such as </em>Live TV<em> in the second screenshot above), it was displayed at the top of the screen.</em></figcaption>

</figure>

</div>

<p>ATT U-verse does a good job of showing the hierarchy of the content that the user is viewing. When the <em>Menu</em> button on the remote is selected, the information structure is clear. The high-level categories (<em>Recordings, On Demand,</em> etc.) are shown, along with the related subcategories (for <em>Recordings: Recorded, Scheduled,</em> etc.) below them. After making a category selection (e.g., <em>Recordings</em>), the main-category menu is no longer needed and is removed. The selected-category heading is displayed boldly and on top of the smaller subcategory menu. By displaying prior selections with this visual hierarchy, it is clear to the user where they are within in the system and how to navigate back out.</p>

<div style="text-align:center">

<figure class="caption" style="display:inline-block"><img alt="ATT U-verse Menu" border="0" height="834" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/09/15/attuverse-flow.png" width="722"/>

<figcaption><em>AT&amp;T U-verse’ hierarchical structure is clear and informative.</em></figcaption>

</figure>

</div>

<h2 id="toc-support-search-4">Support Search</h2>

<p>With the sheer volume of programming content available, providing a content-search feature is crucial. This feature should be obvious and easily accessible.</p>

<p>In Time Warner Cable’s interface, the search feature is not visible on the screen, but instead users must know to select an arbitrary blue-square button labeled <em>B</em> on the remote control. Since the button is not labeled <em>Search</em>, the user needs to rely on explicit instructions within the interface or in the physical user manual to learn how to access system search.</p>

<div style="text-align:center">

<figure class="caption" style="display:inline-block"><img alt="Time Warner Cable guide" border="0" height="410" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/09/15/timewarnercable-guide.png" width="720"/>

<figcaption><em>Time Warner Cable’s interface showed instructions across the bottom of the screen to tell the user to access the search feature by pushing the blue </em>B<em> button on the remote.</em></figcaption>

</figure>

</div>

<p>In contrast, Google Fiber’s search feature is easily discoverable and accessible. There is a large search button on the remote itself and it is also listed as one of only five options in the main menu. Since locating content is a key user task in the television domain, it’s important that this feature not be hidden from the user.</p>

<div style="text-align:center">

<figure class="caption" style="display:inline-block"><img alt="Google Fiber's main menu" border="0" height="415" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/09/15/googlefiber-menu.png" width="720"/>

<figcaption><em>Google Fiber’s main menu exposed search as one of only 5 options in the main menu.</em></figcaption>

</figure>

</div>

<p>Google Fiber, AT&amp;T U-Verse, and Time Warner provide very similar solutions when it comes to the search feature itself. While entering text into the search field with a remote comes with the same challenges it always has, within these constraints, each service has created a usable search feature. They’ve done so by implementing a few simple time savers to make entering a search query more bearable:</p>

<ul>

<li><strong>Autocomplete search terms. </strong>In each service, when users begin entering a search query, the result area displays partial matches to the search term, potentially saving them from entering the entire query.</li>

<li><strong>Show recently searched items. </strong>Google Fiber users can also select items from their search history and can clear their history, a helpful privacy-sensitive piece of functionality welcome on a shared device.</li>

</ul>

<div style="text-align:center">

<figure class="caption" style="display:inline-block"><img alt="Google Fiber search feature" border="0" height="410" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/09/15/googlefiber-search.png" width="720"/>

<figcaption><em>Google Fiber search feature displayed the TV’s search history for quick access to commonly searched terms.</em></figcaption>

</figure>

</div>

<ul>

<li><strong>Optimize the alphanumeric text-entry pad. </strong>Time Warner Cable gets the prize for the most efficient selection grid: by showing numeric options as part of the set of symbol choices displayed by default. This makes entering numbers into the search query easier than on Google Fiber (screenshot above) or AT&amp;T U-verse, which both require a deliberate action to enable numeric selections.</li>

</ul>

<div style="text-align:center">

<figure class="caption" style="display:inline-block"><img alt="Time Warner Cable search feature" border="0" height="411" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/09/15/timewarnercable-search.png" width="720"/>

<figcaption><em>Time Warner search feature used numeric selections as part of the default keypad.</em></figcaption>

</figure>

</div>

<figure class="caption" style="display:inline-block"><img alt="ATT U-verse search feature" border="0" height="415" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/09/15/attuverse-search.png" width="720"/>

<h2 id="toc-support-decision-making-5">Support Decision Making</h2>

<p>The interface must not only support users in locating specific programs, but it must also support content discovery and browsing. As users browse large sets of content like the channel guide or the <em>On Demand</em> programs, the design of these screens should provide the right information in the right way at the right time. Enough detail should be shown on the screen to prevent unnecessary digging through pages and pages of content and to decrease browsing effort.</p>

<p>Time Warner Cable and AT&amp;T U-verse’s <em>On Demand</em> movie-guide screens make browsing for a movie labor intensive. These services only display the cover photo of the movie on the screen. While it can be nice to see a visual representation of the movie, often the text on this artwork is not readable at the size it is displayed and it forces users to arrow through the grid to get the name of the movie.</p>

<div style="text-align:center">

<figure class="caption" style="display:inline-block"><img alt="ATT U-verse movies" border="0" height="424" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/09/15/attuverse-movies.png" width="720"/>

<figcaption><em>AT&amp;T U-verse’s movie-search feature did not show the movie title label with the thumbnail. Users had to select a thumbnail to see the name of the movie. The green banners at the bottom of the thumbnails indicated the rental period and sometimes obscured the text on the movie cover artwork.</em></figcaption>

</figure>

</div>

<p>Google Fiber shows imagery along with text labels to aid in decision making. <a href="/articles/marginalia-of-web-design/">Relevance-enhanced image reduction</a> is used to create images that focus on a small, salient element, as opposed to brutally resizing a complex image with many elements. This solution allows quick scanning and enables people to get the information needed for choosing a movie without selecting and revealing the title on each thumbnail.</p>

<div style="text-align:center">

<figure class="caption" style="display:inline-block"><img alt="Google Giber movie selection" border="0" height="398" loading="lazy" src="//s3.amazonaws.com/media.nngroup.com/media/editor/2015/09/15/googlefiber-movies.png" width="720"/>

<figcaption><em>Google Fiber’s </em>On Demand <em>movie-selection menu showed movie artwork along with the title and year the movie was released.</em></figcaption>

</figure>

</div>

<h2 id="toc-conclusion-6">Conclusion</h2>

<p>While a <a href="/articles/tv-meets-the-web/">smart TV set is still not a computer</a>, it’s picking up computer-like elements such as <a href="/topic/navigation/">navigation</a> and generating a user experience that’s far from the old world of simply watching live broadcasts. The <a href="/articles/media-velocity-tv-vs-the-web/">granularity of user decisions</a> is getting finer, increasing the importance of the user experience and usability of the provided TV interface. As with any other domain, we must understand the primary role of the UI as it relates to the user’s goals. For television interfaces, the primary user goal is to find the right content as quickly and seamlessly as possible. Supporting this goal is crucial to designing a usable and enjoyable television interface.</p>
